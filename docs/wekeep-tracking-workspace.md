# 위킵 송장 작업

`실제 출고 · ERP → 4 위킵 송장 가져오기`에서 처리한다.

1. 출고 기준일, 위킵 주문 유형(B2C / 사입형 B2C / B2B), 판매처를 선택한다. 판매처 개별 원본은 기존 열 매칭 설정으로 자동 인식하거나 직접 지정한다. 출고프로그램의 통합 출고 양식은 각 행의 `판매처`, `수령자`, `핸드폰` 열을 직접 읽으며 단일 판매처 설정으로 덮어쓰지 않는다.
2. 판매처별 출고 파일을 입력한다. 파일 원본, 행 정보, 입력 작업자, 입력 시각을 저장한다. 동일 날짜·유형·파일·매핑의 재입력은 기존 작업을 다시 불러온다.
3. 위킵 주문등록 시작일과 종료일을 지정하고 조회한다. 출고 기준일과 위킵 등록일은 별도 값이다. 계정은 PC별 DPAPI로 암호화해 저장할 수 있고, 조회 브라우저에서 직접 로그인해도 된다.
4. 위킵 주문 상세검색의 모든 페이지와 `getOrderDetail` 조회 응답을 읽는다. 위킵 내부 주문번호와 판매채널을 다시 검증한 뒤 판매처주문번호, 수령인, 휴대폰, 우편번호, 기본·상세주소, 송장, 추가송장, 상품정보를 저장한다. 목록과 상세의 송장이 다르면 두 값 모두 대조한다.
5. 주문번호는 구두점까지 보존한다. 주문번호 후보가 없으면 상품주문번호로도 조회한다. 배송정보는 공백과 전화번호 표기를 정리하여 비교한다. 필수 배송정보가 없거나 다르면 검토 필요로 남긴다. 여러 송장은 자동 확정하지 않는다. 여러 판매처에 동일 번호가 있으면 위킵의 판매처 근거가 없는 후보는 자동 매칭하지 않는다.
6. 위킵 상세의 품목에 명시된 판매처주문번호는 각각 대조한다. 주문번호가 달라도 수령인·연락처·우편번호·주소가 모두 같은 후보는 검토 화면에서 확인할 수 있다. 배송지가 같다는 이유만으로 송장을 복사하지 않는다. 작업자가 합포장 후보를 선택하고 비교 화면에서 사유를 입력해 수동 연결할 수 있다.
7. 매칭 완료 주문을 확정한다. 확정 송장은 재조회로 덮어쓰지 않는다. 재조회 결과가 다르면 확인 사유에 표시한다. 기존 FLOW 주문이 판매처·계정·주문번호·상품행·배송정보로 하나만 연결되는 경우 그 주문의 송장 정보에도 반영한다. 실제 출고, 출고수량, ERP 상태는 이 기능에서 변경하지 않는다.
8. 선택 작업 또는 당일 전체 판매처 송장 엑셀을 다운로드한다. 판매처 원본에 확정 송장을 반영한 XLSX/XLSM/CSV 파일도 저장할 수 있다.

## 엑셀 형식

첫 시트 `택배출고`는 기존 Shipping의 11열 순서이다.

`주문번호 | 판매처 | 상품명 | 수량 | 수령자 | 핸드폰 | 우편번호 | 주소 | 배송메세지 | 송장번호 | 일련번호`

송장번호는 J열이다. 식별번호는 텍스트로 저장하여 앞자리 0을 유지한다. 미확정 행에는 송장을 기록하지 않고, 두 번째 `송장 확인 상태` 시트에 상태·사유·확정 작업자·시각을 기록한다. 확정건만 다운로드를 선택하면 미확정 행은 두 시트에서 모두 제외한다. 파일에는 공식 판매처 업로드가 요구하는 별도 열을 임의로 추가하지 않는다.

## 저장과 호환성

로컬 SQLite에 `tracking_jobs`, `tracking_rows`, `tracking_queries`를 추가한다. 원본은 작업별 BLOB으로 보관하여 같은 파일명으로 다음 날 입력해도 이전 원본을 보존한다. 백업과 공유 작업공간 스냅샷에도 포함한다. 공유 형식은 8이다. 형식 1~7은 계속 읽을 수 있으며, 이전 프로그램은 형식 8을 읽지 못하면 연결을 중단해 새 정보를 덮어쓰지 않도록 기존 보호 동작을 유지한다. 함께 사용하는 PC는 이 기능이 포함된 버전으로 업데이트해야 한다.

조회는 백그라운드에서 실행하고 SQLite 및 화면 적용은 UI 스레드에서 수행한다. 조회 중 작업이 바뀌면 결과 반영을 중단한다. 공유 저장의 기존 버전 충돌 검사도 유지한다. 로그인 계정과 브라우저 프로필은 FLOW 전용이며 Shipping의 설정을 수정하지 않는다.

1.9.22부터 기존 버전에서 잘못 인식한 통합 출고 파일도 재조회 시 저장된 원본과 행 번호·주문번호를 대조하여 판매처와 배송정보를 복구한다. 확정 송장은 보존한다. 위킵 페이지는 번호 링크와 이미지 형태의 다음 페이지 묶음 버튼을 모두 처리한다.

## 검증

- 자동 테스트: 중복 파일, 영속성, 배송정보 불일치·누락, 구두점이 다른 주문번호, 복수 송장, 합포장 후보, 위킵 상세 신원 검증, 수동 연결 사유, 재조회 보호, 동시 변경, 주문 송장 연동, 공유 스냅샷, 엑셀 및 원본 출력.
- 2026-10-08 위킵 실조회: B2C 주문 2건의 송장과 수령인·휴대폰·우편번호·기본/상세주소 수집 성공. 서버 주문 변경·출고 처리·송장 등록은 실행하지 않았다.
- 사용자의 업데이트 배포 요청에 따라 1.9.21에 포함한다. GitHub Release와 자동 업데이트 서버는 같은 기준 커밋과 실행파일로 게시하고 다운로드 해시를 검증한다.
- 1.9.22 수정 검증: 2026-10-06 실조회 461행을 수집하고, 공유 작업 복사본 135행의 연락처와 11개 판매처를 복구했다. 118행은 주문번호와 모든 배송정보가 일치했고, 17행은 송장 발급 대기였다. 실서버의 작업 데이터나 위킵 주문을 수정하지 않았다.
