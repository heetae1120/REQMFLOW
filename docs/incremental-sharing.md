# Supabase 공유 동기화

설정·백업의 Supabase 공유 작업공간에서 프로젝트 사용자로 로그인합니다. 자동 동기화를 켜면 30초 간격으로 버전 번호를 확인하고 변경된 행만 전송합니다. 계정 세션과 로그인 정보는 각 PC에서 DPAPI로 보호하며 다른 PC에 공유하지 않습니다. 저장된 세션을 재사용하고 인증 실패 시 반복 로그인하지 않습니다.

`004_flow_incremental_sync.sql`은 `flow_sync_meta`, `flow_sync_records`, `flow_sync_members`를 추가합니다. 기존 작업 스냅샷을 서버에서 한 번만 분해하여 초기 자료로 사용합니다. 기존 `reqm_workspace_state`, Shipping 테이블 및 파일은 변경하지 않습니다. 현재 프로젝트의 기존 Auth 사용자들을 default 작업공간 구성원으로 등록합니다. 이후 추가된 사용자는 관리자가 구성원으로 등록해야 합니다. 익명 사용자는 공유 자료를 읽거나 저장할 수 없습니다.

수정은 행별 예상 revision을 확인한 뒤 하나의 트랜잭션으로 저장합니다. 전역 버전은 행 변경과 함께 잠금 상태에서 증가합니다. 삭제 행은 tombstone으로 남겨 다른 PC의 오래된 자료가 자동으로 복원되지 않도록 합니다. 로컬 캐시와 공유 기준은 `flow_local_baseline`, `flow_local_cursor`, `flow_local_conflicts`에 저장하고 DB 백업에 포함합니다. 이 로컬 관리 테이블은 다른 PC로 보내지 않습니다.

최초 연결 시 이미 작업 자료가 있는 PC는 서버와 다르면 자동으로 덮어쓰지 않습니다. 충돌 자료 비교에서 항목별로 이 PC 또는 서버 자료를 선택합니다. 로컬 변경이 없는 행만 새 서버 값으로 반영합니다. 초기 충돌도 로컬에 저장하여 전체 자료를 계속 내려받지 않습니다. 출고프로그램 기준의 고정 품목 목록은 프로그램에 포함된 목록을 따릅니다. 이전 스키마에 없는 필드는 기본값으로 비교하여 실제로 같은 ERP 행을 충돌로 오인하지 않습니다.

같은 주문 identity가 다른 행 ID로 공유되면 이미 입력된 로컬 주문을 기준으로 유지합니다. 서버의 중복 주문과 그 주문에만 연결된 요청·출고 행은 tombstone으로 정리하고, 송장 추적 행은 유지 주문 ID로 연결합니다. 이 자동 정리는 동기화 계획과 행별 revision 검증을 거쳐 저장하며, 다른 동기화 오류는 상태 표시줄에 구체적인 사유를 표시합니다.

이미 삭제가 확인된 주문 ID를 다른 PC의 뒤늦은 송장 추적 갱신이 다시 참조하면, 삭제 주문을 복원하지 않고 추적 행의 주문 연결만 해제합니다. 송장번호·조회 결과·확정 이력은 보존하며, 수정한 연결은 revision 검증을 거쳐 공유합니다. 삭제 기록이 없는 알 수 없는 주문은 임의로 연결 해제하지 않으며, 충돌 검토를 위해 이 PC에 유지한 주문의 연결도 보존합니다.

에이블리 금액 열이 누락된 주문도 명시적으로 저장한 품목 매칭은 표시·공유합니다. 금액은 ERP 전표에 필수이므로 금액 검토가 끝날 때까지 주문 상태는 검토 필요로 유지하고 출고·ERP 생성을 막습니다.

한 번의 변경 저장은 최대 10,000행·12MiB이며 과도한 데이터는 서버가 거부합니다. 파일 원본은 해당 파일 행이 변경되거나 새 PC가 처음 연결할 때만 전송합니다. 대용량 파일 증가와 조직의 다른 프로젝트 사용량은 여전히 Supabase 사용량에 영향을 줍니다. 무제한 사용을 보장하지 않습니다.

HTTP 401·403 및 인증 관련 400은 다시 로그인을 요청하고 자동 재시도를 중단합니다. 402·429는 사용량·요청 제한으로 표시하고 중단합니다. 단순 네트워크 장애는 30, 60, 120, 240, 300초로 간격을 늘립니다. 같은 행이 동시 수정되면 서버가 변경 전체를 거부하고 최신 자료를 대조하도록 합니다. UI 변경은 UI 스레드에서 수행하고 네트워크는 단일 작업 스레드에서 처리합니다.

새 버전은 GitHub만으로 배포합니다. Supabase의 1.9.35·1.9.36 실행파일과 기존 latest.json은 구형 클라이언트 전환용으로 유지합니다. 2026-10-13 구버전 실행파일 27개를 `%LOCALAPPDATA%/REQM-Local/backups/supabase-updates-20261013`에 SHA-256 목록과 함께 백업 후 업데이트 캐시에서 제거했습니다. Shipping 저장소와 주문 원본 버킷은 정리 대상이 아닙니다.

현재 PC의 초기 전환 전 DB는 `backups/before-incremental-sharing.sqlite3`, 설정은 같은 이름의 `.settings.json`에 보관합니다. 기존 서버 스냅샷은 그대로 유지됩니다. A·B·C 모두 1.9.37 이상으로 업데이트해야 하며, 구형 공유 클라이언트는 새 증분 자료를 보지 못합니다.
