## 구현된 범위

- Supabase 이메일·비밀번호 로그인과 이메일 로그인 링크 요청
- `flow_sync_meta`, `flow_sync_rows`, `flow_sync_apply` 기반 증분 동기화와 행 단위 충돌 방지
- 주문 파일 입력, 품목 매칭, 출고 요청, 실제 출고 등록
- B2C 위킵 송장 파일 대조와 송장 포함 파일 다운로드
- 판매처·품목·수량·금액·주문번호별 1회 배송비를 반영한 ERP 미리보기와 다운로드
- 구성 품목이 같은 세트는 색상이 달라도 가격 템플릿을 재사용하는 가족 규칙
- 출력 이력 원본 다운로드, 설정 및 웹 JSON 백업
- 소스 파일·결과 파일의 큰 payload는 목록 동기화에서 제외하고 다운로드할 때만 조회

## 알려진 제한

- 판매처 사이트 자동 로그인·주문 자동 수집·위킵 자동 조회는 브라우저 보안과 자동화 환경 때문에 아직 데스크톱 기능을 사용한다.
- 암호화된 Excel과 판매처별 특수 Excel 처리 일부는 데스크톱이 필요하다.
- 웹 백업 JSON은 웹 작업용이며 기존 데스크톱 전체 복원 파일과 동일하지 않다.
- 첫 배포 후 실제 계정으로 주문 1건 수준의 읽기·쓰기 확인이 필요하다.

## 보안 및 운영 원칙

- Supabase 공개 publishable key만 브라우저 코드에 둔다. 비밀번호, 세션, 서비스 키는 GitHub나 배포 파일에 저장하지 않는다.
- 로그인 세션은 탭의 `sessionStorage`에만 보관한다.
- 모든 데이터 접근은 Supabase RLS와 `flow_sync_members` 구성원 검사에 맡긴다.
- `source_files`, `artifacts`, `tracking_jobs`의 큰 payload를 전체 동기화하지 않는다. 사용량 초과 재발을 막기 위한 핵심 제약이다.
